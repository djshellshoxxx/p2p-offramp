# Optional courier reference models

This package implements bounded local portions of Section 03. It is not installed in the default application or messaging registry. It has no wallet, contract, relay, device, camera or network executor. Removing it preserves the basic escrow. Nothing here establishes a cash amount, note authenticity, physical proximity, delivery, fiat finality or a right to release, refund or slash basic principal.

These are local implementation claims, not completed module qualification. Models are in-memory unless the encrypted container-secret consumer explicitly performs a G02 commit. They do not acknowledge network delivery or promise crash-safe receipt/locker replay. Callers must not connect the reducers directly to external actions. A signed physical acknowledgment remains an attributed claim.

## Required trusted composition

`createCourierVerifier` requires a selected profile, exact key/signature decoders, a current-owner callback, domain-aware hash/verification ports and a terms-bound signer policy. The package chooses no signing curve, signature encoding or challenge/receipt domain separator. The ports must authenticate the exact detached canonical payload and the supplied native trade binding, shipment and terms context, plus the reviewed outer envelope's version, sender, recipient and message ID. That outer envelope is not defined or emitted here. Imported signature/status/reviewer labels never mint `CourierEvidence`; evidence belongs to one live verifier and cannot be serialized and reimported as authority.

Callbacks are local reviewed composition capabilities, not peer-provided functions or stored approvals. Mutation admission is set before calling them; they must report actual current actor/terms/clock/custody observations. Clock failures or rollback stop handoff/recovery acceptance. Verification ports receive disposable owned bytes and an abort signal. Each hash/signature operation has a five-second local resource bound. A timeout permanently closes that verifier: an uncooperative port cannot accumulate further physical operations behind a timed-out request. Closing the verifier cancels pending work, clears its buffers and synchronously closes dependent container-secret services.

The container-secret service additionally requires a live G02 session, a private 32-hex record slot, actual publication observation, canonical owner/current-head authority and a generation floor from that authority. A floor is never inferred from an imported backup. Missing slots with a nonzero floor and stored generations unequal to the independently current floor refuse use. A caller must close the service/verifier on owner changes; G02 lock and verifier close synchronously clear borrowed buffers. Provisioning rechecks the no-custody condition across asynchronous dependencies, at the G02 mutation guard and after persistence. Reveal rechecks expiry after persistence before returning bytes. A durable disclosure-attempt log may remain when expiry prevents the response. After process loss or an uncertain commit, recover the current generation head before creating a replacement; a refusal after an already committed generation does not authorize retry. The private ledger is a versioned local storage format, not a new message/signature standard.

Reveals return borrowed `Uint8Array` objects. `release`, subsequent reveal for the same reader, compromise, retirement, close and vault lock zero owned buffers. Expiry is checked on access and prevents further reveals. JavaScript strings, caller-made copies, screenshots, existing backups and remote copies cannot be reliably erased or revoked. Retiring a secret does not unpublish it. This package has no secure-element/nonextractability claim.

Locker windows are diagnostic observations: a valid projection still has `nativeUnlockAllowed: false` and `oneUsePersistenceVerified: false`. `markSendStarted` models entry into uncertainty but performs neither durable storage nor a send. A signed door status does not resolve an earlier command's outcome without an exact reviewed device result protocol. There is consequently no reset/resubmit method after an uncertain send. Fee/stake numbers similarly describe local claimed balances, never native solvency or spendability.

## Missing profile decisions

Activation requires exact reviewed contracts for the signing/encrypted extension carrier and hash domains; message-ID replay ownership; durable handoff/challenge acknowledgments; sealing-attestation generation binding; canonical generation/backup recovery; fee/collateral vault and unbonding/finality; and device identity, authenticated counter/result semantics, trusted time, one-use persistence and operator recovery. No default profile or adapter is supplied for these gaps. An exact profile can make further engineering feasible; production review/trust choices are separate qualification gates.

The short CIT-02 illustration and local unit clocks are isolated coordination examples. They are not an integrated G32 activation profile: a composed route must independently satisfy G32's 1–24 hour response window and seven-day total cap.

## Verification

From the repository root:

```sh
node --import ./scripts/test-support/register-tsx.mjs --test packages/courier/test/*.test.mjs
node node_modules/typescript/bin/tsc --noEmit
npm run check:boundaries
```

Tests cover malformed/tampered canonical bytes, context and opaque-evidence refusal, fixed independent container preimage/hash bytes, entropy failure, unauthorized disclosure, encrypted write-before-reveal, lock during commit, generation rollback, purpose-owned cleanup, nonce substitution, expired/uncertain clocks, receipt forks and missing acknowledgments, no-response/lost-parcel recovery, unknown unlock outcome, jam and conflicting sensors, integer bounds and conservation. Signing/device ports in fixtures are deliberately synthetic and unqualified. The fixed all-zero secret is test-only.

`test/fixtures/container-python-v1.json` was independently calculated with Python `json.dumps(..., sort_keys=True, separators=(',', ':'), ensure_ascii=False)` for the fixture's ASCII strings and safe integer, then `hashlib.sha256(domain_utf8 + canonical_utf8)`. Its stored preimage and digest are checked against the TypeScript implementation rather than recomputing expected values with the implementation under test.
