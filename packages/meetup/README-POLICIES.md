# Optional meetup policy models (T56)

This supplements the frozen T41 [README](README.md). The default app, extension registry, provider catalogs, TURN configuration, sensor owners and map renderer remain absent. These modules have no networking, wallet, cash, courier, proof or settlement executor. Manual/core exits do not depend on their availability.

The SDP parser accepts a narrow data-channel-only subset; unsupported attributes are rejected, not stripped. It is not a complete WebRTC implementation or a covert-channel/anonymity proof. A relay candidate or pair is a supplied claim until an actual reviewed browser/transport owner observes it. The relay configuration helper is a caller-owned diagnostic template, not a provider allowlist. TURN credentials are ephemeral caller inputs; there is no static credential or fallback. Existing private transport status cannot authorize RTC.

Venue records use the Ed25519 key/signature sizes explicitly specified by MEET10. The verifier port receives the module domain separately from canonical unsigned bytes; the package does not invent a delimiter/framing rule. MEET11 does not specify its revocation signing domain, so that port receives `domain: null` and must implement a separately reviewed contract. Synthetic test ports establish neither profile. Public-place/provenance/license moderation is a trusted local policy operation; a signature alone never passes it. Sorting is deterministic ID ordering, not an invented safety/reputation score. A correctly signed malicious venue may still lie.

## Native local persistence

Venue high-water and replay diagnostics use the actual public G02 vault/session lease and atomic CAS interfaces. New internal storage formats are `p2p-offramp/venue-history/local/v1` and `p2p-offramp/meetup-replay/local/v1`; the chunk container is `p2p-offramp/meetup-local-parts/v1`. They are local preferences, not protocol messages or approval tokens.

A trusted composition supplies a 32-hex head slot and the actual current canonical profile/slot owner. Part IDs are the first 16 bytes of SHA256 over UTF8(`p2p-offramp/meetup-local-parts/v1/<head-id>/<index>`). Each 96 KiB part is bound to the namespace, index, length and exact SHA256. The head and all part puts/deletes commit atomically in one native CAS. The diagnostic state cap is 2 MiB (22 parts), inside G02's existing per-record/snapshot bounds. Existing foreign/future preferences, opaque trade records and all core data are preserved. A foreign head/part, wrong schema, missing part, digest mismatch, conflict, lock or uncertain write refuses; there is no destructive reset, migration, eviction of core records or automatic retry.

The directory caps combined imported entries and retained record/revocation keys at 5,000 and encoded input at 10 MiB. High-water expiry is 90 days from its observation/effective time; replay IDs expire logically at session end or 24 hours from local session creation, without renewal by duplicate reception. Expiry cleanup occurs on explicit local access; there is no background writer or guarantee of erasing ciphertext/backups. Native storage capacity can refuse rather than sacrifice unrelated data. Actual tests cover a 5,000-record history across G02 record boundaries.

This persistence is diagnostic local history, not global rollback resistance. Reinstall, a different profile, cleared storage or restored older backups can remove previously observed high-water. `isStorageCurrent` must be supplied by the real profile owner. It cannot manufacture a signed current distribution/generation head. Fresh installs still need the approved current bundle policy described by MEET11. No imported status/reviewer label becomes trust authority.

## Lifetimes and provenance

Long-lived models bind the full native TradeBinding, trade hash, terms hash, account and peer through a required current-owner capability. Mutating/job admission occurs before any input/profile callbacks; scope and native session are checked after awaits and at native writes. Owner callbacks that close the model cannot return a late successful result. Scope loss/lock closes owned work, aborts callbacks and clears owned bytes. Native/profile jobs have a five-second local deadline; the bounded 5,000-entry directory operation has 30 seconds. Timeout permanently closes that owner so a physically uncooperative port cannot accumulate further jobs. Caller copies and JavaScript strings cannot be reliably erased. Constructors validate local options before capturing native sessions and close owned leases on every later failure. Gateway projections recheck actual T41 consent after clock callbacks and inspect its native abort state at final publication. The replay session cutoff is checked at native CAS, after commit and at publication; an already committed attempt remains uncertain when its response is refused.

The geofence has no default distance adapter. Its supplied numerical adapter sees a borrowed coordinate buffer cleared immediately after use. The private previous-sample buffer is cleared on reset/end/owner loss; a 30-second silence timer ends the generation even without another sample, subject to browser scheduling. Hide/lock still must revoke the existing T41 consent. No timer can create sensor/network work. Confirmation and geodesic callbacks are followed by fresh clock/owner checks. Raw coordinates, distance, bearing and accuracy never appear in observations or claimed-event payloads. No output claims GPS truth, physical presence, anonymity or money movement.

## Exact unresolved contracts

- MEET09 requires the full TradeBinding in the hashed JCS object, but its `DistanceChallenge` DTO omits that field. The exact hash field mapping must be resolved before a portable challenge codec. Commitment primitive, chart/projection, circuit/verifier/setup and authenticated proof adapter also remain undefined. No proximity binding/proof implementation or badge is supplied.
- MEET05/06 and MEET12 require authenticated non-text participant payloads, signed channel challenge/fingerprint domains and replay ownership. The current core carrier is text-only; no new Nostr kind, NIP-17 body or signing bytes were invented.
- MEET14 prose requires a source URL while its signed DTO omits the field. The validator follows that exact DTO and rejects added URL/style/glyph/sprite fields until the schema is versioned. Content registry/signature framing and compression/parser profiles remain required.
- MEET14's 100 MiB encrypted cache exceeds G02's 8 MiB snapshot architecture. This slice does not reinterpret the vault format, spread data across new profiles or pretend to implement that cache. Cache architecture/retention and decoder isolation require their separate contract.
- TURN/browser routing, approved public publishers/datasets, trusted sensor authenticity, distance proofs and physical safety remain unavailable without their specific reviewed profiles and evidence. Constructor callbacks are reviewed bundled composition, never peer-provided approval functions.
