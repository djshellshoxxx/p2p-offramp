# T47 independent review: corrected hostile-error and cleanup boundaries

Approved final frozen repair. Read-only reviewer; no production source changes. Scope is the three existing services and two added hostile-boundary test files, including compatibility with T34 current-backup verification and existing durable/CAS semantics.

## Original repairs independently verified

Direct probes confirmed hostile `getPrototypeOf` throws from vault store/list/get and identity captureSession now become fixed Result diagnostics, and backup errors become a fresh BackupError with a fixed enum-derived message. Foreign code accessors/unknown codes/prototype traps are not serialized or broadly coerced. Known error classes are checked inside guarded code, only own data-property codes from a fixed enum survive, and foreign message/stack/cause values are discarded. BackupError construction first checks string type before own-key lookup.

Native signal controls use captured aborted getter and EventTarget listeners rather than caller-shadowed public fields/methods. Malformed/hostile signal objects fail before acquiring recovery capacity or a vault lease. Direct shadowed-native-signal export followed by a second normal export returns NOT_FOUND twice, not permanent BUSY. Own listener removal cannot mask a durable result or skip global recovery release. Native platform brand behavior is used rather than nominal same-realm instanceof; an additional Node VM-context/different-prototype genuine signal probe returns NOT_FOUND before abort and CANCELLED after abort (`/workspace/work/t47-independent-realm-probe.log`). This is not browser iframe/cross-device qualification or a claim that every transparent Proxy is rejected on every platform.

## Additional reviewer finding resolved

The first candidate still invoked identity lease.dispose directly inside finally, revocation and lockAll. A valid lease whose disposal threw PRIVATE_DISPOSE made create() escape a raw cleanup exception instead of its intended fixed unsupported-provider result; it also skipped profile-tail/listener release. This could mask a durable fallback and stop later cleanup. Root admitted this P2 and owner reproduced it.

Final code isolates external lease teardown at all three sites after local revocation. Per-buffer intrinsic fill is independently isolated so a malformed provider buffer cannot stop remaining cleanup. New tests demonstrate two queued same-profile failures both settle with fixed diagnostics and actual signal listeners detach. A real native-vault/Noble identity creation winning late cancellation still returns its locked durable reference despite throwing lease cleanup; the persisted identity remains discoverable, can be unlocked twice, and lockAll/dispose revoke all handles without throwing. The repair does not claim it can force a faulty injected cleanup provider to release its own resources; local authority and operation results no longer depend on it.

## Compatibility and bounded work

Vault control construction now precedes tail replacement, so failed listener setup cannot wedge the selected profile queue. Verification releases owned bytes/recovery capacity if control setup fails. Backup listeners/register/cleanup are inside the slot-release finally. Recovery slots stay held until actual ignored native work drains; logical cancellation does not create more capacity. T34 exact-row authentication, per-await guards, no-write verification and proof scope are unchanged. CAS still catches same-revision replacement; completed durable commit/add/adoption still wins late cancellation and returns its narrow receipt. No success or signing authority is inferred from foreign error fields.
