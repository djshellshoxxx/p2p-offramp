## Correctness and authority

The supplied complete backup is copied and bounded, its canonical envelope checksum checked, and its envelope required to match the selected session's exact committed envelope. Actual Web Crypto opens it with the supplied file passphrase independently of the prior unlock. The decoded complete snapshot must match the authenticated session snapshot, including opaque future consumer records. Persisted rows are read before and after authentication; a changed row locks the stale session. The result contains only profile/revision/scope and envelope/file SHA-256, not records, keys, ciphertext or session credentials. Verification never writes, restores, unlocks or establishes spending/chain authority.

Worker verification is private state bound to the exact handle, generation, profile and revision. No public/imported receipt setter exists. Unlock, export and fresh-key restore do not establish verification; restored profiles require their own current exported file. Selected mutation attempts invalidate the old fact, including failed/uncertain writes. Recheck always calls native `assertFresh` before returning a Worker-owned fact; copied receipt JSON cannot revive it. Document reply parsing additionally rejects wrong-profile receipts.

## Lifecycle, resource bounds and privacy

Verification holds the existing shared recovery slot and selected session tail until actual native work settles. Cancellation/lock do not release capacity early. Session/current-selection and request deadline guards surround every relevant await, including the final persisted-row read and Worker reply. Lock, timeout, profile reopening and scope changes suppress late success. Service-owned backup copies and derived material are cleared/disposed; caller bytes remain owned by the caller. This is not physical erasure of immutable strings, browser internals or every GC copy.

UI is an explicit file/passphrase authentication operation with a distinct current-revision recheck. Display is explicitly point-in-time and excludes wallet spending keys, relay history, chain truth and independent retention. User input changes clear the display receipt; passphrases clear on submission, files are bounded before reading, transient owned bytes clear in finally, cancellation/unmount/scope change abort and suppress late work. Receipt display requires exact facade identity, profile and selection scope. Replacement facade setup clears stale busy/notice/receipt state even if numeric scope is reused.
