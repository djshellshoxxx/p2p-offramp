# Proof / zkTLS profile

Decision: local source/parser and lifecycle engineering is READY; no bank-proof provider is selected. A genuine receipt proof is not specified by the TLS library alone. The existing basic escrow must never consume this as release authority.

Primary snapshots: TLSNotary alpha.15 commit [`47aee45`](https://github.com/tlsnotary/tlsn/tree/47aee45b53e06648c1b2ad3689b367b8c923fdec), [WASM README](https://github.com/tlsnotary/tlsn/blob/47aee45b53e06648c1b2ad3689b367b8c923fdec/crates/wasm/README.md), [Cargo manifest](https://github.com/tlsnotary/tlsn/blob/47aee45b53e06648c1b2ad3689b367b8c923fdec/crates/wasm/Cargo.toml). The separately pinned [upstream README](https://github.com/tlsnotary/tlsn/blob/24b10ba21bf36c3fd3de709e7eccd8308bb64207/README.md) explicitly warns against production use and recommends tagged evaluation. Application contract to freeze before a genuine provider:

- `FiatProofRequest`: exact trade/chain/deployment binding, accepted terms hash, sourcePolicyId, statement version, unique challenge and disclosure digest. Provider identity is an explicit allowlisted profile, never remote JSON `true`.
- Exact rail/currency, minor-unit scale0..6, uint128 positive amount, uint64 UTC seconds, beneficiary/reference policy and locale/timezone/status parser. Witness response<=1MiB, <=16 field spans, raw strings<=512UTF-8 bytes and account/reference<=256bytes. Every claimed semantic field and observation timestamp must be authenticated; pending/reversed/unknown never means posted. No FX tolerance or partial-payment sum in v1.
- Source policy must choose hostname/SNI, certificate/authentication model and roots, TLS/proxy coverage, authenticated request/response bytes and span extraction. Repo SourcePolicy requires exact normalized HTTPS origin/path, redirect rejection, <=1MiB response and <=300s freshness. A synthetic JSON bank fixture cannot establish a real bank's semantics or irreversible payment.
- Pin exact provider/SDK commit, Rust/clang/wasm-pack/optimization/lockfiles, exported WASM/API and worker ownership; then obtain WASM/circuit/key/parameter bytes and hashes, verifier/public-signal order, commitment preimages/hash and >=16-byte private salts. This packet does not substitute TLSNotary attestation for an unspecified application circuit.
- Notary identity/governance/key rotation, verifier trust boundary, endpoints, G05 egress and credential isolation remain unset. Credentials/cookies/TLS secrets are not witness fields, diagnostics or generic backups.

Ready local slice: strict request/witness/statement models against public synthetic responses, exact byte-span coverage, duplicate-key/UTF-8/amount/timezone failures; an isolated proof-job supervisor with one active job/no queue, 1MiB witness, 2MiB proof, 256MiB WASM maximum, 8MiB cumulative network budget, 120s monotonic deadline and 15s heartbeat watchdog. These limits come from the repo proof budget; they are not measurements of alpha.15 feasibility. Parent-owned worker termination and late-result suppression can be tested without a provider or bank. Build pinned upstream synthetic server/notary fixtures only after artifact/toolchain intake; retain explicit test-only provenance.

Reusable source: `packages/extensions/src/registry.ts`, `packages/transport/src/policy.ts`, `packages/schemas/src/registry.ts`, existing Worker/vault lifecycle boundaries. No existing proof verifier is claimed. Exact project contracts: zkTLS provider interface, receipt proof statement/witness, TLS source authentication and proof-job resource budget under `feature_1.2_zktls_fiat_verification`.
