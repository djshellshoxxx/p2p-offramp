# Mobile external-wallet handoff profile

Decision: session/return/expiry engineering is READY; no mobile connector, wallet URI or production session is selected. Existing injected EIP-1193/EIP-6963 wallet work and browser emulation do not establish mobile handoff support.

Concrete candidate: [WalletConnect Ethereum provider2.26.0](https://github.com/WalletConnect/walletconnect-monorepo/blob/63094dcb6fded05dcbc2b08b8895ada75a31dcb5/providers/ethereum-provider/package.json), commit63094dcb6fded05dcbc2b08b8895ada75a31dcb5; dependency Reown AppKit1.8.19 and UniversalProvider2.26.0. Its [API README](https://github.com/WalletConnect/walletconnect-monorepo/blob/63094dcb6fded05dcbc2b08b8895ada75a31dcb5/providers/ethereum-provider/README.md) requires a projectId, uses optionalChains (chains is deprecated), and documents session/chain/account events. A project registration or paid/public relay action was not performed.

Primary Sign specification snapshot [`ecbbf6e`](https://github.com/WalletConnect/walletconnect-specs/tree/ecbbf6e114687812fd0366fb59dff8c0a8e3c9ec): [namespaces](https://github.com/WalletConnect/walletconnect-specs/blob/ecbbf6e114687812fd0366fb59dff8c0a8e3c9ec/docs/specs/clients/sign/namespaces.md), [session data](https://github.com/WalletConnect/walletconnect-specs/blob/ecbbf6e114687812fd0366fb59dff8c0a8e3c9ec/docs/specs/clients/sign/data-structures.md). It distinguishes pairing from a session, session topic/controller, negotiated CAIP chains/accounts/methods/events and expiry as seconds. The source data-structures page still calls itself v2.0-rc; do not assume every mutable doc heading proves SDK2.26.0 compatibility. Evaluate exact SDK/spec fixtures together.

Freeze these application fields before a real mobile adapter:

- Connector/package/source/artifact lock; EVM versus Solana separately; allowed chains and exact methods/events. Request least privilege: examples including personal_sign/eth_signTransaction do not authorize adding them to this app.
- Selected wallet applications and exact versions, supported universal/deep-link scheme/host/path, registered return origin/path and allowed launch contexts. No generic arbitrary URI navigation or raw transaction bytes from a return URL.
- Explicit caps for URI bytes, namespace/account/method counts, pending requests and session storage; pairing/session/request expiry and renewal policy, encrypted session storage ownership, disconnect/revoke/account/chain change semantics, lost-session recovery and disposal. Pairing URI/symmetric key is sensitive session material, not a public invite or diagnostic.
- G05 egress/relay/project ID policy and strict-mode behavior; a hosted relay's availability, metadata or billing does not follow from the SDK interface.
- G12 checkpoint before leaving: operation ID, actual chain/account generation and encrypted pending intent; return event merely triggers fresh wallet/native reconciliation. No automatic submit/resend or URL-supplied finality.

Ready local slice: a bounded external-wallet connector port with no default provider; synthetic negotiated namespace/session fixtures; wrong account/chain/method, expired/pending response, forged callback origin, repeated pageshow/visibility, cancellation/disposal and suspend-clock failure tests. Explicitly label fake relay fixtures; no real account or registered callback is required to implement the local state machine. SDK/WebWorker/redirect egress inspection precedes its eventual integration.

Reuse `packages/wallet/src/evm-adapter.ts`, discovery/evm-submit tests, `packages/domain/src/tx-lifecycle.ts` and the current local native journey. Keep custody/serialization in those existing modules. Physical Android/iOS wallet app-switch/locked-screen/file-share/low-memory recovery and exact wallet/version observations are later measured qualification rows, not inferred from Chromium emulation, a viewport or a successful mocked return. No mobile hardware-wallet support is claimed.
