ScopeLift calls `getSharedSecret` without a compression argument and hashes the returned bytes. The declared noble2.0.0 API defaults to compressed33-byte SEC1. These are different preimages and different recipients. The SDK's reviewed generation test includes an expected-address TODO; its self-consistency tests do not resolve the conflict with the published notebook. ## Exact local contract for a separate implementation

For BOTH profiles, inputs carry explicit localProfileId, application network context and schemeId1. The curve is secp256k1 only: field p=`fffffffffffffffffffffffffffffffffffffffffffffffffffffffefffffc2f`, scalar order n=`fffffffffffffffffffffffffffffffebaaedce6af48a03bbfd25e8cd0364141`. Reject other schemes/curves/networks and unknown keys/versions; never substitute SHA3-256, SHA256, HKDF or another curve.

- Public points are canonical compressed SEC1, exactly33bytes, prefix02/03, x<p, on-curve, non-infinity. A raw meta-address is33bytes (same public key for spend/view, allowed by the standard) or66bytes (spend first, view second). A URI wrapper accepts only exact `st:eth:0x` plus66/132hex digits (75/141characters), using strictly lower-case ASCII hex, with no whitespace, percent escapes or Unicode lookalikes. Reject alternate chain prefixes, suffixes, truncated/uncompressed/hybrid points. SDK prefix/length checks and URI parsing alone are insufficient; wrapper must do actual curve/network validation.
- Ephemeral sender entropy and viewing private scalar are separate Worker-private32-byte big-endian values with1<=k<n. CSPRNG samples reject0/out-of-range before curve operations with at most128attempts then fixed unavailable; production generation never accepts caller test entropy or derives it from a vault key/wallet signature. Caller-supplied deterministic entropy is restricted to an explicitly local test entrypoint. Spending input is PUBLIC key only; no product spending-secret collection or computeStealthKey API is authorized. Standard single-key meta-addresses may be compared on the sender side using public input, but a recipient viewing key would then also be the spending secret. Therefore a recipient scanner must require a separately owned viewing handle and a distinct spending public point; single-key/equal-point recipient profiles stay unsupported outside explicitly public synthetic fixtures. Verify the handle-derived viewing public point agrees with the declared viewing point. No wallet seed/private-key import can be relabeled as view-key enrollment.
- Compute Q=e*Pview for sender or v*E for scanner; hash the EXACT profile preimage above using Keccak-256. Let h be unsigned big-endian digest; tag is its first byte. For this intentionally limited local profile, refuse h=0 or h>=n rather than silently inventing a modulo/KDF compatibility rule. Rare exceptional-input behavior remains part of later interoperability review. Compute Pstealth=Pspend+hG, reject infinity, address=last20bytes of Keccak-256(x32||y32 of Pstealth). Return compressed33-byte E, tag1byte and address20bytes. No derived spending secret leaves a Worker or enters diagnostics.
- Use the already-pinned secp/Keccak primitives through their existing provenance boundary; no new hand-rolled curve arithmetic, duplicate crypto package or wallet authority. Viewing capability is session-bound/revocable. Generation/cancellation/lock/clock changes suppress late outputs; owned buffers/references are cleared best effort without a physical-erasure claim.

## Announcer/scanner contract and bounded local work

Official ABI: `Announcement(uint256 indexed schemeId,address indexed stealthAddress,address indexed caller,bytes ephemeralPubKey,bytes metadata)` and `announce(uint256,address,bytes,bytes)`. Topic0 is in the vector JSON; exactly4topics, each32bytes. Indexed addresses use canonical ABI padding. Event data is canonical two-dynamic-bytes ABI; reject invalid/overlapping/unbounded offsets, wrong lengths, malformed points and metadata without its first view-tag byte before curve work. Emitting an announcement does NOT itself transfer assets.

Proposed LOCAL resource profile (client limits, not ERC-wide wire maxima): ephemeral key exactly33bytes; metadata1..256bytes; canonical ABI data<=448bytes; <=2000blocks/request, <=1000logs/page, <=10000candidate derivations/job. The latter three are existing repo scanner limits. Overbudget/incomplete pages do not advance a complete checkpoint. Additional metadata stays opaque; native/token selector/amount guidance in the ERC is not bank/transfer proof. A matching tag is only a filter; compare the full derived address. Candidate display has no balance/payment/spend authority.

Pure local scanner fixtures can cover wrong emitter/scheme/profile, false-positive tags, points, duplicate `(blockHash,txHash,logIndex)` events, page truncation, pause/dispose, checkpoint crash and synthetic reorg rewind. Real scanner activation additionally needs selected network/announcer runtime-code hash, native canonical anchors, explicit chain reorg/finality window, bounded RPC egress and an encrypted atomic checkpoint namespace. Do not invent a new G02 record kind. The ERC reports singleton `0x55649E01B5Df198D18D95b5cc5051630cfD45564`; an address in documentation does not verify code on any selected chain.

Remaining predecessors: resolve/narrow the published shared-secret encoding conflict with independent vectors under an explicitly evaluated profile; select chain/deployment and reorg policy; bind any new stealth recipient/announcement commitment into signed NEW unfunded terms; qualify an actual external-wallet spending/recovery/gas workflow without collecting its secrets. Professional cryptographic/privacy review and measured interoperability precede activation. Amounts/timing/sender/announcer/gas remain public, and neither profile makes EVM escrow anonymous.
