# Optional Waku and XMTP profiles

Decision: offline exact-codec/ownership evaluation is READY for these concrete source candidates. Neither adapter is selected or enabled, and neither replaces existing Nostr/NIP-17. They are different protocols, not one shared proof of delivery/privacy.

## Waku

The old waku-org/js-waku URL redirects. A directly accessible primary candidate is [logos-messaging/logos-delivery-js](https://github.com/logos-messaging/logos-delivery-js/tree/0ca94f3c8beda0fba2962c3daae17b3ec689ae49). At this exact snapshot, `@waku/sdk` is0.0.37, `@waku/core`0.0.41 and libp2p2.8.11, with transitive ranges still requiring a resolved integrity lock. These are observed package versions, not an assertion they are the latest release. Reviewed [message.proto](https://github.com/logos-messaging/logos-delivery-js/blob/0ca94f3c8beda0fba2962c3daae17b3ec689ae49/packages/proto/src/lib/message.proto) and [StoreV3](https://github.com/logos-messaging/logos-delivery-js/blob/0ca94f3c8beda0fba2962c3daae17b3ec689ae49/packages/proto/src/lib/store_v3.proto).

Actual message bytes: payload field1, content_topic2, optional version3, timestamp10 (sint64), meta11, rate-limit proof21 and ephemeral31. StoreV3 uses request ID, pubsub/content-topic filters, time bounds, message hashes and an exclusive pagination cursor plus uint64 limit. Optional timestamps/ephemeral flags do not establish remote deletion. The reviewed [LightPush constants](https://github.com/logos-messaging/logos-delivery-js/blob/0ca94f3c8beda0fba2962c3daae17b3ec689ae49/packages/core/src/lib/light_push/constants.ts) expose `/vac/waku/lightpush/2.0.0-beta1` and default `/vac/waku/lightpush/3.0.0`; do not guess a single historical protocol path from a moved URL.

Repo application envelope remains signed/independently verified, <=32768bytes, expires locally after300s; content topic exposes protocol/version only; dedup4096-entry FIFO; history explicit consent and <=100messages/query. Waku ACK means peer propagation/response only. No fallback to Nostr, plaintext or direct egress without explicit new consent.

Missing selected fields: network/cluster/shards, pubsub/content topics and exact Relay/Filter/Store/LightPush codec revisions; authenticated peer IDs/bootstrap/discovery and connection caps; G05 paths for every SDK WebSocket/DNS/discovery request; existing envelope mapping, encryption recipient rules, retention/replay and optional RLN trust/cost policy. Offline protobuf fixtures and a bounded two-local-peer interoperability harness can be built before production peers are chosen, clearly named synthetic network. No live public bootstrap is authorized by this packet.

## XMTP

Candidate [xmtp-js commit8993ef2](https://github.com/xmtp/xmtp-js/tree/8993ef24144532e53fdfcfd04eddf27dce8a5a53), browser SDK7.0.0 with `@xmtp/wasm-bindings`1.11.0-nightly.20260603.89c3fc3, per [package](https://github.com/xmtp/xmtp-js/blob/8993ef24144532e53fdfcfd04eddf27dce8a5a53/sdks/browser-sdk/package.json). A latest repository release query returned an agent-SDK tag; that is not a browser pin. [Client source](https://github.com/xmtp/xmtp-js/blob/8993ef24144532e53fdfcfd04eddf27dce8a5a53/sdks/browser-sdk/src/Client.ts) owns a WorkerBridge, installation/inbox state, consent/preferences and close behavior. WASM and Worker assets require actual lock/integrity/build/egress intake, not just a package name. Its `Client.create` calls init and, unless disableAutoRegister is set, register; merely constructing this convenience flow is not an offline/consent-free operation. Do not invoke it as a harmless capability probe.

Missing selected fields: protocol generation and network/environment/gateway, signer and wallet-to-inbox association validation, installation creation/revocation limits, participant authentication, conversation consent, app trade-envelope mapping, encryption/database-key ownership, cursor/retention/recovery and G05 enforcement of SDK-owned worker sockets. Identity association signatures are not spending consent. Never use a convenience randomly generated EOA signer as a production external wallet.

Ready local work: pin build artifacts and inspect network/worker creation; decode synthetic identity-association/participant/error fixtures; implement no-network empty-registry refusal and disposal/late-receive tests against an explicit adapter interface. Real SDK local-server interoperability requires documented server/network artifacts, not invented success fixtures. If egress cannot be brokered, strict mode stays unsupported. Future end-to-end identity/privacy/retention review is separate from these local tests.

Reusable local evidence: `packages/messaging/src/durable-chat.ts`, native NIP-17 tests, extension negotiation, transport guards and core-only build boundaries. Those qualify only the implemented Nostr path; they do not certify Waku or XMTP. Switch protocols only through new signed unfunded terms, never silently mid-trade.
