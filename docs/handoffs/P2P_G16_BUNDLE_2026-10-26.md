## Behavior and product scope

`verifyEvmAgreementBundle` checks an actual private agreement against one captured G16 public terms/domain snapshot and two distinct seller/buyer EOA acceptances. It reuses existing private/capability encoders and SHA-256, exact EIP-712 digest and EOA verifier. No new crypto algorithm or provider qualification.

Before any await it snapshots exact data-only outer/domain/terms/private/acceptance records, encodes the private agreement/capabilities under existing bounds, copies intrinsic signature bytes and validates role/account/hash consistency. Both signatures are cryptographically verified against the corresponding stored seller/buyer over the same digest. Order/revision must match; computed privateAgreementHash and capabilitiesHash must match the signed public terms. Imported approval flags or changed self-declared acceptance hashes cannot replace signature verification.

Result contains only captured public termsHash/accounts, **testOnly=true** and **economicPreparationAllowed=false**. No private agreement, salt, instructions, signatures or capability policy is returned. Verification of nonempty capability commitments verifies signed data consistency only; it does not approve or activate an extension/custody policy. No state engine, plaintext persistence/cache or send/retry/clear surface was introduced.

This advances M2.1 signed terms: the actual private agreement must match what both account keys accepted. It does not prove fiat payment, physical identity, latest advertisement revision, registry/deployment trust, chain time/finality, nonce consumption, inclusion or funding eligibility. Expiry/funding checks remain separate native/contract preflight; contract-wallet EIP-1271 is unsupported. Never use this result as spending authorization or silently export it into the app.

## Bounds, lifetimes and privacy

Existing encoder bounds retained: private bytes<=16KiB; instructions<=4KiB UTF-8; <=8 sorted unique capability entries; fiat uint128>0/scale0..6; revision uint64>=1; public principal uint256 and native times uint64. Exactly2 distinct role records, each canonical64-hex digest/20-byte account and65-byte r||s||v signature; existing low-s and v27/28 rules unchanged. No arbitrary JSON signing or ABI.

All input payload/signature snapshots precede asynchronous hashing. Worker-owned isCurrent/signal checks suppress stale completion before/after awaits. Abort immediately clears owned arrays; all exits clear owned private/capability/signature arrays. Private encoded bytes clear immediately after their own hash, before waiting on the public capability hash. Generation mismatch without an abort event is observed when the pending hash settles and then clears owned data; owners should abort their scoped job for immediate cancellation wipe. Underlying hashing can finish after abort. Caller-owned strings/inputs, encoder internal temporary allocations and native crypto internals are outside these arrays' ownership; no physical-memory-erasure guarantee.

Optional SHA callback is trusted local test instrumentation for the existing helper, not an imported choice/approval. It must never be built from peer/QR/file data. Defaults remain native WebCrypto; context functions are worker-owned lease/generation authority. No private payload is emitted in diagnostics. Strict descriptor-based parsing rejects unknown fields/accessors/prototypes/sparse arrays; intrinsic signature copying bypasses caller length/iterator/subarray overrides and rejects incompatible/revoked proxies with INVALID_INPUT.
