# Privacy, encryption and recovery

Implemented local vault records are encrypted using native WebCrypto AES-GCM with passphrase-derived key wrapping. Local tests cover authentication failures, corruption, concurrent writes and fresh-key recovery. This is scoped local evidence, not independent cryptographic approval. Unlocked origin code, extensions, weak passphrases and the OS can expose content.

Message-content encryption has vector and local test evidence; relay metadata, recipient copies and public advertisements remain separate. No browser-wide private routing is inferred from encryption or connectivity. Public chains expose transaction metadata. Selected route indicators must reflect current broker evidence; unknown wallet routing remains unknown. Stealth, location privacy and physical erasure are unsupported release claims.

Saved reviews include private payment instructions; deletion is logical and does not erase backups or browser/OS remnants. Local backup-verification authenticates the current encrypted record set at a fixed profile/revision during the current unlocked session. It authenticates only the file supplied for this check against that profile revision. It does not execute a restore or authorize transactions. Cross-tab changes are detected on explicit recheck; the displayed result is point-in-time. Exported files still require their own recovery check. Restore writes a distinct fresh-key profile and retains the source. Restored identities require explicit consumer adoption; pending transactions require native reconciliation. Unknown broadcasts must not be blindly resent. [Release and incidents](Security-and-Release.md).
