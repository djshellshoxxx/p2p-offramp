# Security and release verification
Never deploy to real funds before escrow invariant tests, fuzzing, browser and mobile compatibility testing, threat-model review, dependency/license review and independent audit. Require signed release manifest and deployed bytecode checks. Explicitly document fiat finality, dispute authority, custody and metadata leakage. No-script portal is read-only; it cannot safely substitute for client-side signing. Public documentation must distinguish planned features from shipped and audited features. Report vulnerabilities privately using the repository's published security disclosure process when available.
