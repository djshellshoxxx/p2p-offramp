## 4. Recommended implementation order after this research

1. **Consolidate PR #26 and repair its verified integration issues.** Inspect current ownership first. Importing upstream code is unlikely to resolve a local listener-count regression or a dropped cancellation signal.
2. **Make the peer-acceptance carrier and core commitments concrete.** Select a versioned schema and signature binding, write independent vectors, then connect the already implemented EVM verifier to two genuinely separate clients.
3. **Complete the static testnet trust/deployment/archive profile.** Reuse existing Sepolia and release tools. A library must not choose the production signing root.
4. **Add focused product capability:** one reviewed QR stack, explicit mobile wallet handoff and targeted browser/accessibility checks. Each should have a small adapter and a measurable user journey.
5. **Implement native Solana/SPL after its profile is fixed.** Keep it independent from EVM and validate real native asset/token behavior.
6. **Evaluate optional providers in independent, inactive intake packages.** Proofs, stealth, maps and routing should each show an artifact-coherent prototype before app integration. Courier, liquidity and arbitration require their separate custody contracts.

This order is an engineering recommendation derived from the actual dependencies. It does not freeze future research, add optional dependencies to basic exits, or authorize live custody/provider activation.

## 5. What “acceptable code” means in these notes

A **preferred candidate** has inspected source that plausibly fits the integration boundary and an identified license at that exact source revision. It has not automatically passed artifact provenance, transitive licensing, security review, browser measurements or the project's acceptance gates. A **reference-only** project can guide independently authored requirements/tests without being imported. A **rejected/deferred** candidate is documented so the next worker does not repeat the same unsuitable search.

No root project license was found in the inspected main/PR #26 root trees; `BasicEscrow.sol` is marked `SPDX-License-Identifier: UNLICENSED`. That is not permission to assume any chosen copyleft or permissive distribution model. Preserve source licenses and notices, select the actual dependency artifacts, and record the distribution decision before copying/adapting code. The existing [attribution record](https://github.com/djshellshoxxx/p2p-offramp/blob/94554ecf9854e4604f9f56afe5bebedeee931994/THIRD_PARTY_NOTICES.md) is the starting point, not an assertion that every new candidate is cleared.

No dependency was installed or imported during this task. Verification for these notes covers source references, pinned repository state and integration-path consistency; it does not claim new application test results or completion of any feature.
