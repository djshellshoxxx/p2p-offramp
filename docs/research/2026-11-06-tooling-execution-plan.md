## 0. Mission, immutable product boundaries and what already exists

Mission: select and qualify useful open-source development tools, run bounded tests on authentic application artifacts, convert confirmed bugs into small test-first patches, verify end-to-end two-client trading, and release only after independent contract, security, wallet, RPC, relay and browser acceptance.

Normative scope: static React/TypeScript/Vite **client-side** application, user-controlled identity and wallet secrets, user-selected RPC/relay infrastructure, versioned noncustodial escrow, explicit encrypted storage and recovery. No app-owned mandatory backend, centralized account database, private-key custody, server-held secrets or unauthorized changes to established escrow rights. Direct browser/wallet/RPC dependencies are disclosed; static hosting does not mean offline settlement. Initial manual fiat payment remains dependent on the **seller's explicit confirmation**; the application neither guarantees fiat receipt/finality nor gives an optional proof provider authority to release already funded escrow. Contract/program rights and deadlines of existing trades must remain stable. Optional zkTLS, reputation, stealth, courier, map and arbitration features cannot block basic exits.

Do **not** restart completed source foundations:
- Existing `packages/{domain,exchange,escrow-evm,chain-evm,identity,nostr-crypto,relay,messaging,storage,transport,wallet,security,diagnostics}`, `apps/web`, `contracts/evm`, and `scripts/` implement substantial local flows, tests and security controls. Distinguish tests/native local execution from a deployed, funds-enabled configuration.
- Read `DEVELOPMENT_ROADMAP.md`, `docs/adr/ADR-CLIENT-SIDE-2026-10-24.md`, `docs/DEVELOPMENT_STATUS.md`, `tasks/todo.md`, `docs/research/2026-11-03/{GAP-MAP,DECISION-QUEUE,CONCURRENT-WORK}.md`, `docs/consolidation/branch-ledger-2026-11-04.md`, and `THIRD_PARTY_NOTICES.md`.
- Read source-pinned extended reuse inventories before introducing anything: [27-record reuse map #32](https://github.com/djshellshoxxx/p2p-offramp/blob/5fec2c6db018868a49c8ce40c21e186cdf702417/docs/research/reuse-2026-11-03/README.md) and [upstream reuse analysis #33](https://github.com/djshellshoxxx/p2p-offramp/blob/977b36654bab2d00ca20c6139398b60c693bab73/docs/research/upstream-reuse-2026-11-03/README.md). #32/#33 are open/unmerged; reference their research, do not count documentation as implemented.
- Cumulative #26 and its #37–#48 split PRs overlap and must not be independently cherry-picked by number. #28/#31/#35 are existing repair/review lanes. #53 foundation boundary and signature gates and #54 recovered core continuation remain open. #50 is an **existing** D5 Option A Solana/Anchor/LiteSVM program with source-local/native and vector tests, NOT a blank requirement. #29/#49 contain owner decision packets; re-read exact accepted wording (D1, D4, D5, D6, D7, D8, D9 reported accepted in unmerged branches) and track D2 trust-root/bootstrap and other outstanding decisions before changing a canonical profile.

## 2. Execution environments and cost policy

- **Here / connector-backed research:** inspect GitHub source, produce independent fixtures, write/review tests or scripts, publish isolated branches/PRs/issues. The connected GitHub API does not expose a Codespaces shell. No unexecuted test counts or claimed wallet signatures.
- **Linux Codespaces:** Node >=24 for this repo, Python >=3.12 for spec checks, Foundry and local Anvil, Rust/Anchor/Solana as needed; Chromium and localhost WebSocket relays; pinned version/lockfiles, disk/RAM caps. Codespace is a development computer, not a continuously running production relay, wallet backend or guaranteed funded-chain environment.
- **Linux GitHub Actions:** existing `.github/workflows/{specifications,vault-foundation,evm-escrow}.yml` for current tests, plus isolated opt-in manual work only after a reviewed workflow. `contents: read`, no privileged deployment secrets, bounded matrix, concurrency cancellation for stale PR heads, sanitized fixture receipts and SHA-checked tools.
- **Solana integration:** match PR #50's documented local `contracts/solana` program/IDL/tests and pinned runtime; run LiteSVM and real `solana-test-validator` against exact SBPF build first. Solana devnet wallet testing is a separate opt-in testnet qualification.
- **Browser/mobile acceptance:** desktop Chromium automation can run on Actions; real wallet extensions, Wallet Standard/mobile app switching, QR cameras, 125/150/200% zoom, on-device recovery and screen readers require compatible devices or an interactive runner. CI screenshots do not certify native device permission behavior.
- **Live Sepolia, Solana devnet, external Nostr relays or proof-provider APIs:** disabled by default, opt-in only with explicit approved test identities, capped cost, source records and no real funds. No production deployment, KYC/fiat service integration or API-billed agent schedule from a research PR.

Default early testing uses deterministic mock wallets, locally controlled Anvil, a local Nostr relay, authored encrypted message fixtures, synthetic SOL/SPL accounts and an empty/fake payment source. External dependency services may be chosen by users in production, but should not become a required application-owned server.

## 6. Review, parallelism, security and stop conditions

- Six logical lanes can research in parallel; only funded/expensive cloud runs need resource scheduling. Do not start persistent cloud workers, new paid API agents, mainnet deployments, faucet scripts or background checks without an approved automation/executor and explicit run authorization.
- Current cumulative #37–#48 may include already-covered work and unresolved D7 optional modules. #50, #53, #54 retain independent ownership. Never merge PR #26 as one clean replacement for source review. Preserve the latest reviewed #29/#49 decision status before implementing commitments.
- First-class invariants: no duplicate economic intent on retries; no forged acceptance, EIP-712 cross-chain/deployment replay, wrong asset/account, backend-owned secrets, unverified RPC/finality, relay AUTH confused with consent, secret in QR/log/build, unauthenticated registry/bootstrap, wallet permission bypass, silent optional authority, or actual loss of original recovery.
- A proof of website/bank *observation* is not a proof of final irreversible fiat settlement. The seller's release/refund economics remain manually risk-bearing. Vendor/service credential collection is a separate approved integration with privacy and terms checks, never a bundled default.
- A Solana simulated localnet result is not a verified devnet/mainnet deployment; an EVM-only preview cannot be relabeled as full M2C. Closed/failed CI, skipped Native/Device tests, historical PR checks and synthetic sig oracle findings are not release evidence.
- No force push, overwrite of shared source, disabling CI/security scanners, hardcoded private key, generated fake owner trust root, blind dependency upgrade, or promotion of unqualified optional packages.
- Work may be started with synthetic fixtures while waiting for real-device and owner prerequisites. Every reported result must state precisely whether it was source-inspected, compiled, locally executed, browser executed, testnet exercised, externally audited or not performed.
