# Optional encryption, client-only anti-abuse and no-script feasibility
## Encryption options
Baseline: authenticated end-to-end encryption for trade chat and sensitive evidence before relay transport; encrypted local vault for trade history and private contact metadata; domain-separated keys and unique nonces. Optional: per-attachment encryption; encrypted downloadable backup using a user-held recovery passphrase and Argon2id with platform-calibrated settings; selective disclosure/redaction of payment evidence; encrypted contact aliases; optional ephemeral session mode with no persistence. Avoid double encryption marketed as a guarantee of anonymity: metadata, wallet signatures, RPC queries and payment rails remain observable. No server escrow of recovery keys. Design recovery tests before shipping encryption. Use reviewed primitives and pinned libraries; no homegrown ciphers. Key erasure on browser/OS is best effort, not forensic guarantee.

## Client-only abuse controls
Simple text challenge or local math/word CAPTCHA only at repeated offer creation, excessive local retry, import floods or other low-cost UI actions. It is **not bot resistance against a malicious automated client**, because code and answers run locally. Combine with size/CPU quotas, schema validation, debounce, concurrency limits, local cooldown, signed/paid on-chain spam economics when relevant, peer blocklists and optional privacy-preserving proof-of-work. No external CAPTCHA service or mandatory remote moderation. Local rate limits cannot prevent network-level Sybil attacks; do not label them network security. Challenges must support screen readers, localization, nonvisual alternatives and accessible retry.

## High-security no-JavaScript mode
Offer an optional static HTML/CSS read-only security portal containing instructions, contract source/hash, deployment manifest, verified public keys, printable paper workflows, transaction verification checklist, security documentation and manually verifiable trade terms. A fully interactive client-only browser wallet, EIP-712 signing, live chain RPC, QR camera scan, WASM cryptography and local encrypted vault **cannot generally be delivered without scripting** in a static GitHub Pages browser app. Never imply no-script mode can securely execute escrow. Optional external wallet command-line/air-gapped flow requires a separate signed protocol and audit; not a web replacement. CSP script-src 'none' for the static portal; no embedded external content or trackers. Provide independent checksums for download bundles.
