# GitHub Codespaces integration, testing and delayed GitHub Pages deployment
Codespaces is an **optional developer test environment**, not a production trusted node, privacy guarantee or place to store mainnet wallet seeds. Prepare .devcontainer/devcontainer.json and pinned Dockerfile or Compose when application code exists. Toolchain: Node LTS pinned, pnpm/npm lock, Foundry, local Anvil, Playwright browsers, testnet mock payment processor, local relay, optional Waku/Nostr simulator, fault-injection proxy, fuzzing tools, containerized wallet-provider mocks and optional browser VNC for interactive UI. Add resource limits, reproducible bootstrap, ephemeral volumes and no privileged Docker unless needed. Use GitHub Actions for repeatable headless tests; Codespaces for interactive reproductions and device/browser debugging.

Wallet tests: local Anvil with throwaway test mnemonic only; mock injected provider and WalletConnect deep-link tests; public testnets with disposable wallets funded by faucet; hardware/real-wallet manual tests only using fresh low-value testnet identities. Never place production private keys in repository, devcontainer, logs, forwarded ports, Codespaces secrets or artifacts. Port-forwarding can expose services; default private, review permissions. Docker/real-wallet scenarios are optional capabilities with clear test matrix and cost limits.

Test layers: unit, contract invariant/fuzz, integration, UI cross-browser, network chaos, accessibility, localization, mobile emulation, security scanner, dependency provenance, malicious RPC/relay and restore-from-backup. Gate merges on automated suites, not only Codespaces manual runs.

GitHub Pages: **do not enable now**. Activate only in near-final release phase after signed release manifest, production CSP, origin/domain phishing guidance, SRI where applicable, independent security audit, deterministic static build, verified deployment hashes, staged preview, custom domain/HTTPS validation and rollback plan. No client-side secrets in Pages configuration; no hosted backend dependencies presented as serverless privacy. Publish read-only security portal separately if needed. See existing static deployment and release specs.
