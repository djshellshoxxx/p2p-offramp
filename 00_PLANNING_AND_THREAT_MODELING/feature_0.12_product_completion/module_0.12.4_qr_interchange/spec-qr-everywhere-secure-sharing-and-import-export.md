# QR-first secure information interchange
Offer QR for non-secret shareable data: order invite, public receiving address, wallet connection URI, public payment request, transaction explorer reference, recovery verification fingerprint, signed release fingerprint and optionally encrypted backup ciphertext. Offer paired scan/upload/paste/download/share-sheet for every QR payload. Provide copy, file and manual fallback for devices with no camera or where scanning the same screen is impossible. Do not automatically make all information QR-shareable: secrets, mnemonic phrases, private keys, decrypted evidence and authentication tokens are excluded by default. Encrypted backup export requires explicit confirmation, recipient awareness and risk disclosure.

Canonical envelope: protocol identifier, version, content type, chain ID where relevant, created/expires timestamps, random request ID, length, payload hash, optional signature and payload; use canonical encoding, size limits, strict schema and origin binding. Never put secrets in URL query parameters or remote QR-generation APIs. Generate and decode entirely on device with reviewed pinned QR library; never embed remote images or scanners. If a payload exceeds safe QR density, prefer downloadable encrypted file with QR carrying only a locally usable hash/reference, or multi-frame animated QR with bounded count, sequence ID, checksum and explicit completion confirmation. Avoid unauthenticated URLs and auto-navigation on scan. Display origin/domain, checksum, amount, chain, expiry and permission request before acceptance. Reject malformed Unicode, oversized decompression, unknown schemes, replay, mismatched chain and stale orders. Camera access is optional, user initiated, revoked after scanning; no images leave device.

Acceptance: QR round trips across iOS/Android/desktop, offline, low-light, printed codes, color inversion, camera denial, interrupted multi-frame, same-device handoff, clipboard poisoning and phishing-code replacement. Export/import must never silently overwrite live trade state. Reference [GhostPay stealth invoice](https://github.com/djshellshoxxx/GhostPay/blob/main/docs/MASTER_BLUEPRINT.md) only as a pattern, not a compatible format until separately specified.
