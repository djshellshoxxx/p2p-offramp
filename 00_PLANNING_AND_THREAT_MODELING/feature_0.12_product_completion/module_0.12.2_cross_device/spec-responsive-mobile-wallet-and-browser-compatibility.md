# Responsive mobile, iOS/Android and browser compatibility
Support 320 CSS px upward; portrait/landscape, 200–400% zoom, safe-area insets, foldable hinges, virtual keyboard, touch and mouse, reduced motion, light/dark/high contrast, RTL, large text, offline/low-bandwidth. Breakpoints should be content-driven, not device-model-driven. Never truncate addresses or irreversible-action warnings without accessible expansion. Minimum 24x24 CSS px target WCAG 2.2 AA, aim 44x44 for primary touch controls.

Matrix: Android Chrome, Firefox, Samsung Internet, Opera; iOS/iPadOS Safari, Chrome, Firefox, Opera (WebKit restrictions vary by OS region/version); desktop Chrome, Firefox, Safari, Edge, Opera; test current and prior major where feasible. WalletConnect/deep links, injected EIP-1193 providers, EIP-6963 discovery, QR wallet handoff, hardware wallet through companion app, returning from background, locked-screen resume, clipboard permission denial, camera permission denial, file upload/download, share sheet, low-memory eviction and private browsing. Do not promise mobile hardware-wallet support until device tested.

Architecture: semantic HTML; progressive enhancement; no hover-only actions; focus-visible, accessible dialogs and announcements; adaptive two-column to single-column layout; sticky action area without covering controls; skeleton loading with textual status; avoid browser-specific APIs without capability checks. Safari storage eviction and private-mode persistence are untrusted; encrypted export and recovery are required. Prefer local-first static build with no third-party analytics. Tests: Playwright Chromium/Firefox/WebKit, Android emulator and physical Android devices, iPhone/iPad real-device Safari, VoiceOver/TalkBack, keyboard-only, 320/360/390/768/1024/1440 widths, 200/400% zoom, intermittent connectivity, locale and RTL snapshots.
