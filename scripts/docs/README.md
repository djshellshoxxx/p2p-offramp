# Unpublished documentation consistency

Run `python scripts/docs/generate.py [commit]` (the bound commit defaults to HEAD and must be reachable from `origin/main`; pass `--allow-local` only for fixtures), then `node --import ./scripts/test-support/register-tsx.mjs scripts/docs/validate.mjs`. Regeneration reads the existing seven hand-maintained wiki pages (it never rewrites them) and writes only their two JSON records. It binds the exact six source/test files and the real UI source catalog to an immutable HEAD commit; these evidence files must match that commit even when unrelated working-tree files are dirty. It intentionally emits `dirtyDraft=true`, empty reviewers, null approved release and null last verified release. Do not interpret dirtyDraft as a clean-build assertion.

The manifest binds each page's locale, topic, known capability IDs and UTF-8 SHA-256. The link report binds local target bytes and heading anchors; HTTPS links, if present, are explicitly unverified. Inputs, symlink components, nonregular files, changing files, oversized files, unknown fields/IDs, duplicate keys/IDs and missing or stale hashes fail closed. Local Markdown links use the bounded inline `[label](path#anchor)` grammar; these authored pages contain no reference links, HTML links or executable examples. New Markdown grammars or examples need an explicit checker extension before use.

`claims-register.json` holds canonical DATA02 descriptions plus exact local evidence and real UI copy-key mappings. Canonical `CLAIM_COPY_BINDINGS` maps the six descriptions to existing `sourceCatalog` message IDs; each entry binds the exact message text SHA-256. The full catalog source byte hash must also match the immutable source commit, so any label edit invalidates consistency until reviewed regeneration. Descriptor-safe copy access rejects getters rather than evaluating them. The validator generates the 0.12.7 ClaimsRegister projection, preserving text/preconditions/exclusions from those records; it never grants review authority. The complete link/hash report is printed to stdout and can be retained by CI. Engineering consistency is **not semantic review, professional cryptographic review, publication, host verification or release approval**. Wiki publication and those approvals remain pending. No default runtime trust seam is installed by this tool.

## Evidence binding and staleness

Each evidence row and the copy source bind the bytes at `sourceCommit`: `sha256(git show <sourceCommit>:<path>)` must equal the recorded hash, otherwise the check fails. Those files belong to other owners and may change later. When the current working-tree bytes differ from the recorded hash the row is reported in `stale` (and the claims that cite it in `staleClaims`, each with `evidenceCurrent:false`); this never fails the check, and a stale claim is never current (`canDisplayTestedClaim` and `claimFor` accept the stale paths and then refuse tested-scoped). Files owned by this tooling (the register, manifest and the seven wiki pages with their link targets) stay strictly checked against the working tree. After a stale report, regenerate on a newer `origin/main` commit.

Two bounds changed from the first extraction. The global link bound is 256 (the maintained pages carry roughly 150 links; the per-page extraction bound stays 128 and the 240-character target limit is unchanged); the boundary is tested at exactly 256 and 257. HTTPS links are listed as `remote-unverified` with no byte hash and are never treated as verified; a non-HTTPS non-local scheme is still refused.
